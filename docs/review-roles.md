# Scoped implementation and review

Roles follow the approved task and actual capabilities—not fixed vendors, node names or benchmark rankings. This document creates no delegation, credential or publication grant. Owner/project authorization is required before launching agents; read-only instructions are not execution containment.

- **Assigned writer:** owns a coherent slice, makes the authorized edits and verifies actual outcomes. One writer per shared worktree/slice; preserve others' work and protected files. Parallel mutation requires explicit nonoverlapping ownership/isolation, not an assumption that a worktree is a sandbox.
- **Independent reviewer, when required:** receives goal/criteria, exact source/diff/candidate and relevant test evidence. Fresh context avoids inheriting the author's conclusions; it does not prove a different model/training lineage. Inspect callers, effects and test oracles, not merely green reports. Return concrete findings/unknowns; no writes, commits or scope expansion unless separately authorized.
- **Task owner:** resolves material behavior/risk/authority decisions and retains established publication/integration permissions. A reviewer verdict is evidence, not acceptance authority or permission to merge.

The writer checks each finding against source/contracts, fixes valid in-scope defects and records why anything is deferred/invalid. Fixes need affected checks and review of the changed blast radius. Escalate material unresolved disagreements, not unsupported preferences; do not silently waive missing proof.

A handoff can be short: approved behavior/scope, repo/ref/files, edit boundary, relevant contract/checks, expected output and stop conditions. Review **meets contract / needs change / unverified**; no finding quota or assurance that all defects are absent. Model capability, vision/tool access and actual runtime permissions are verified for the task, not inferred from historical profile claims.

This rebuild specifically requires a fresh read-only subagent gate per chunk. Consumer projects use their own adopted review process; no extra mandatory agent/human ritual is implied for every small fix. Existing fleet governance is outside this portable guide.
