# Bounded consumer cold start

Start with the [adoption skill](../skills/adopt-coding-standards/SKILL.md), [manual status](adoption-status.md) and actual [unit acceptance](../HANDOFF.md). This is a worked route, not an installer, enrollment, release or grant to modify real projects. Choose a source/target and obtain the existing owner's authority first.

## Select, preserve, compose

1. Record the actual source clone/ref and selected files, target ownership/ref/status, existing instructions/Make targets/scripts/manager/lock/license. Preserve custom rules and other agents' work. Missing genuine adoption history stays **unknown**; an invented version stamp does not fix it.
2. Merge `templates/AGENTS.md` into consumer `AGENTS.md`; fill name, exposure, source facts, actual commands and local constraints. Fill `templates/SYSTEM_MAP.md` from the real copied components/callers/state/failure routes. Copy `docs/quality-contract.md` to the same consumer path; its consumer profile/map links must resolve. Do not copy maintainer root identities/maps or historical archives.
3. Choose only a compatible overlay. For the [Node/TypeScript reference](../templates/typescript/README.md), follow its README: selected configs/native hook file, package snippet merged into the actual manifest, exact `scripts/check-package-manager.mjs` path, both example and test under `src/schemas/`, Make targets merged rather than replacing existing targets. Keep the project's scripts/name/license/customizations. Optional mutation is not a bootstrap requirement. If the [architecture method](architecture-review.md) is useful, copy it beside the shared contract; do not invent components to fill a diagram.
4. Check every copied/local link and remove all profile/map placeholders. A source overlay README contains **kit-relative** links; read it at the source, not by blindly transplanting it into an arbitrary consumer directory. Write concise consumer-local setup instructions using actual paths. Preserve applicable source notices/license obligations without replacing the consumer's license. No private vendor policy bodies belong in consumer payload.

## Execute meaningful selected checks

Provision verified project-local tools under the authorized environment, not global/system changes by default. For this selected reference, Node24+/pnpm10.34.3 and matching locked dependencies/native scanner/hook tool must exist. Existing verified tools can be reused; disclose that this is not a pristine toolchain test.

First adoption deliberately uses `pnpm install` to generate the consumer graph; inspect resolution, source/integrity, audit and lifecycle/build-script decisions. Later use `pnpm install --frozen-lockfile`. Do not copy a maintenance fixture's lock as alleged proof the consumer graph was freshly resolved. Then follow the overlay's actual Make lint/format-check/typecheck/test/test-coverage commands and install/test the selected hooks. Native Gitleaks must be verified before its system hook; a green skipped hook is not execution. A staged-diff hook is not a whole-directory scan.

Meaningful violations must fail at the intended check with the correct diagnostic: e.g. TS2322, Biome `noExplicitAny`, a real failed assertion, unimported-source coverage loss. Missing tools/arbitrary nonzero are not those outcomes. Keep original failures, restore exact clean inputs, observe read-only behavior where promised and make ordinary local commits only after clean gates. Do not install/execute a vulnerable application, weaken tests or bypass hooks to demonstrate enforcement. The reference tests exercise parsing and a caller stopping before effects; they do not establish authorization, HTTP/database integration or deployed Node/browser behavior.

## Report and propose updates without erasing rules

Use [manual status](adoption-status.md), not a nonexistent checker. Keep facts separate: selected source bytes/ref, genuine old/customized baseline, configured controls, actual results, review and owner approval. A merged AGENTS/Make/manifest is **customized**, not exact upstream ownership; absent old bindings are **unknown**, not guessed stale/compliant. Genuine different unit refs are **mixed**, not one forged version. Session/history-only changes outside selected inputs do not show unit-content changes.

For an update proposal, compare actual old/new selected source and local edits; identify each needed merge, preserved custom rule, source approval/compatibility uncertainty and checks required. Write a separate proposal only. Recompute target file/ref state to show the proposal left it unchanged; that observation is not a general path/merge-safety guarantee. Apply/install/commit/push/merge/deploy only under their separate existing authority. No updater/catalog/receipt/registry/broker or live enrollment is implemented.

The C13 disposable exercise is evidence for its selected composition/environment only. Other overlays retain their separate native acceptance scopes; all-seven presence, a copied profile, hashes, pins, audits or green hooks do not prove full applications, hosted enforcement, authentication, containment or publication/legal rights.
