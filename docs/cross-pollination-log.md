# Cross-pollination log

Append-only record of Recon/Audit cross-pollination rounds — see `docs/multi-agent-roles.md`. Each entry is a short record of one relay round, not a transcript. Purpose: evidence that the workflow described there is actually being followed, and precedent for future sessions to pattern-match against.

Adopting projects: copy this file (reset to just the format below) into your own `docs/` directory.

## Format

```
## YYYY-MM-DD — <branch/PR>
- **Asked:** <what was requested, and how it was scoped>
- **Returned:** <finding, "no issues found", or a question>
- **Resolved:** <integrated as-is / integrated with changes / escalated to human owner / dismissed as false positive — with why>
```

## 2026-07-04 — TheWarRoom `session/glm-audit-fixes-2026-06-28` (PR #1)
- **Asked:** Not a fresh dispatch — this is the formalizing pass for TheWarRoom's 2026-06-28 GLM 5.2 whole-repo de-slop audit (three passes: engine/rubrics/composition/harness, stores/DB/primitives, ingestion pipeline; ~30 findings, verdict at `TheWarRoom/docs/build-handoffs/audit-glm-2026-06-28.md`), which ran and shipped its B6-watch-list items at the time but was never logged here and left its 2 MAJOR findings untriaged against current source. This round re-verified both MAJORs against `main` (`8f57874`, 6 days and 4 build sessions later).
- **Returned:** Both MAJORs still live, unchanged: (1) `playerid.New` accepts signed numeric strings (`"+99"`, `"-5"`) — `strconv.Atoi` allows a leading sign, `strings.TrimLeft` only strips `'0'` runes, so a signed id survives into the canonical form (`"+99"` → `"0+99"`) and silently fails to cross-reference against the same player's unsigned id (AD-06/RISK-003). (2) `madden.fillRatings`' string-rating skip guard (`val[0] == '"'`) doesn't catch a JSON `null`, which unmarshal-succeeds to `0` with no error — a silent zero on K's 0.60-majority Madden signal.
- **Resolved:** Both fixed on TheWarRoom `session/glm-audit-fixes-2026-06-28` (PR #1) with planted tests confirmed to fail pre-fix (`git stash` round-trip) and pass post-fix; `make lint` 0 / `go test -race ./...` green. The ~25 remaining MINOR/IMPROVEMENT/NOTE items were reviewed but not individually re-triaged this round — none are BLOCKER-class, several (duplicated helpers, doc drift) are logged as future M17 candidates in TheWarRoom's own `docs/cross-pollination-log.md`, which this round also adopted into that repo. This satisfies the standing cross-pollination pilot: stayed in scope (verified against source, didn't act on unconfirmed leads), flagged the still-open MAJORs to Christopher before fixing rather than silently patching, both findings were real (not noise), and the relay (audit → dormant → this triage pass) still surfaced a live data-integrity bug 6 days later — the overhead was worth it.

## 2026-07-24 — `templates/astro/` pre-commit hook (PR pending, `session/astro-cross-poll-fixes`)

- **Asked:** GLM 5.2 (via OpenCode on bird, replacing the retired Antigravity per `docs/multi-agent-roles.md`'s current mapping) was given a self-contained, closed-ended request: actually exercise all 6 files in `templates/astro/` against real installed tools in a scratch Astro project, and answer 4 specific yes/no questions with evidence — does Prettier really reformat a malformed `.astro` file, does `tsconfig.json`'s `astro/tsconfigs/strictest` extend resolve, does `astro check` correctly pass/fail, and does the pre-commit hook actually modify a file or silently no-op the way the Bash overlay's shfmt hook once did. This overlay had never been run against real tools since it shipped 2026-06-10.
- **Returned:** Q1–Q3 confirmed YES with command-level evidence (Prettier reformats correctly; `strictest` resolves via tsc's resolver — Node's `require.resolve` blocking it was a correctly-identified red herring; `astro check` passes clean code and fails a deliberate `string`→`number` prop mismatch with `ts2322`, with `strictest`'s activity independently confirmed via an unrelated `ts6133` unused-variable catch). Q4 (the pre-commit hook) was not answered — GLM's session hit a real, correctly-diagnosed **BLOCKER**: the shipped `rev: "v3.4.2"` for `pre-commit/mirrors-prettier` doesn't exist as a tag, so the hook fails at environment init before it can even run. GLM's session was cut off mid-diagnosis of the deeper cause.
- **Resolved:** Triaged against primary source, not taken on faith. `git ls-remote --tags` on `pre-commit/mirrors-prettier` confirmed the newest real tag is `v3.1.0` — the BLOCKER is real, not a hallucination. Reproduced the failure directly, then went a step further than GLM's cut-off session: repinning to a real tag (`v3.1.0`) still doesn't work — `additional_dependencies`-installed packages live in the hook's *isolated* node environment, and Prettier 3's ESM plugin resolution for `prettier-plugin-astro` cannot reach across environments (confirmed: `[error] Cannot find package 'prettier-plugin-astro']`, even with `NODE_PATH` set). Installing `prettier`+`prettier-plugin-astro` as the project's own local `node_modules` (which `package.json.snippet` already provisions) and invoking `npx --no-install prettier --write` resolved cleanly and reformatted the file correctly. Replaced the remote `mirrors-prettier` hook with a `repo: local` hook using that mechanism; verified fixed, end-to-end, through `pre-commit run` itself (`Failed - files were modified by this hook`, real before/after diff) — not just the standalone CLI. `templates/astro/.pre-commit-config.yaml.snippet` and `README.md` updated with the fix and the "why" explanation; README's stale Phase 2/3 status footer also corrected in the same pass.

**Pilot note:** this is the first cross-pollination round run against the *current* Recon/Audit mapping (GLM 5.2 on bird) rather than the retired Antigravity — the workflow held unchanged (self-contained scoped prompt → relay → Builder triage against source → integrate). It also caught the fourth instance of this repo's recurring "plausible-looking config silently doesn't work until actually run" failure class (after the AWS-example-key, shellcheck SCRIPTDIR, and shfmt `args:` catches) — this one a full two layers deep (bad pin, then a structural env-isolation bug even once pinned correctly) rather than a single config-typo fix.
